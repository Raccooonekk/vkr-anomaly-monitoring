# VKR Anomaly Monitoring

Репозиторий содержит реализацию конвейера разработки системы предиктивного мониторинга аномалий производительности в микросервисной архитектуре.

Основной набор данных: `gagansomashekar/microservices-bottleneck-detection-dataset`.

## Назначение проекта

Система преобразует исходные CSV-файлы с трассировками и ресурсными метриками микросервисной архитектуры в агрегированное представление состояния системы, формирует временные признаки и обучает модели машинного обучения для прогнозирования будущего значения `p95_latency` и риска аномалии производительности на следующем временном шаге.

## Реализованные этапы

1. Предобработка исходных файлов из `/kaggle/input`.
2. Агрегация метрик задержек, CPU, памяти и сетевой активности.
3. Формирование производных, динамических и лаговых признаков.
4. Разметка аномальных состояний по квантильным порогам, рассчитанным только на train-части.
5. Формирование предиктивного датасета с горизонтом прогноза `t+1`.
6. Логическое объединение обработанных part-dataset через manifest без физического копирования данных.
7. Обучение регрессионных и классификационных моделей.
8. Сохранение моделей, метрик, предсказаний и HTML-отчета в `/kaggle/working`.
9. Веб-визуализация результатов мониторинга и ML-эксперимента в Streamlit-панели.

## Веб-панель мониторинга

Для подготовки скриншотов к главе 3 ВКР реализовано приложение доступа к результатам мониторинга:

```bash
streamlit run dashboard/streamlit_app.py
```

Панель читает реальные результаты из `/kaggle/working/vkr_anomaly_monitoring_outputs`. Если результаты полного Kaggle-пайплайна еще не сформированы, приложение автоматически использует демонстрационный набор данных, чтобы можно было проверить внешний вид дашбордов. После появления реальных отчетов, предсказаний и обработанных part-dataset демонстрационный режим отключается автоматически.

В интерфейсе реализованы разделы:

- обзор мониторинга и прогноз `p95_latency` на следующий временной шаг;
- анализ сервисов, RPC-карта сценариев `compose`, `home`, `user` и ранжирование сервисов по риску деградации;
- сравнение регрессионных моделей с baseline по MAE, RMSE и R²;
- журнал риск-событий и контроль нештатных ситуаций при сбоях источников данных.

## Запуск на Kaggle

Notebook находится в директории `kaggle_notebook`. GitHub Actions workflow публикует notebook в Kaggle и ожидает результат выполнения. Если Kaggle сообщает ошибку или выполнение не завершается за отведенное число проверок, workflow завершается с ошибкой.

## Локальная структура результатов

Все результаты сохраняются только в `/kaggle/working/vkr_anomaly_monitoring_outputs`:

- `predictive_processed_dataset` — обработанные part-dataset;
- `merged_predictive_manifest` — manifest логического объединения;
- `models` — обученные модели;
- `predictions` — предсказания на test-выборке;
- `reports` — метрики и HTML-отчет;
- `metadata` — служебные JSON-файлы.

## Важные ограничения

- исходные данные не сохраняются в GitHub;
- токены Kaggle не хранятся в коде;
- запись в `/kaggle/input` запрещена;
- объединение больших обработанных наборов выполняется логически через manifest;
- разбиение train/val/test выполняется хронологически без перемешивания.
